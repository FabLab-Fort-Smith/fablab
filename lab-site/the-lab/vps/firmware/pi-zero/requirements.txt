# Pi Zero W edge-node runtime deps. Install on the device with hash verification (supply chain —
# @rules/std-supplychain):  pip install --require-hashes -r requirements.txt
#
# `cryptography` is the one security-critical runtime dependency (the edge VERIFIES Ed25519 envelope +
# audit signatures and derives HMAC blind indexes — a compromised build here forges door grants), so it and
# its transitive closure (cffi, pycparser) are EXACT-pinned and hash-verified. --require-hashes demands the
# WHOLE closure be pinned, so all three are listed. The NFC/GPIO libs are lazy-imported by the driver you
# select in config.json → optional, listed as comments below; install them separately (also hash-pinned).
#
# Hashes are the authoritative PyPI sha256 for the sdist + the abi3/cpXX wheels covering dev/CI (x86_64) and
# a 64-bit Raspberry Pi OS (aarch64), glibc + musl / cp311 + cp313. On a 32-bit (armv6/armv7) Pi OS that
# installs from piwheels the wheels differ → regenerate the pin for that exact platform + Python:
#   pip download -r requirements.txt --no-deps -d /tmp/wh && pip hash /tmp/wh/*   (or pip-compile --generate-hashes)

#   **NOT AFFECTED**. That CVE is an OpenSSL raw-public-key (RPK) TLS-handshake abort in the wheels'
#   bundled OpenSSL. This edge does ALL TLS via the Python stdlib `ssl` module (system OpenSSL), and uses
#   pyca/cryptography ONLY for Ed25519 signature verification + HMAC blind-index derivation — no TLS, no
